# Little Things I Am Learning

A collection of technical concepts, useful commands and lessons learned while building projects.

## 1. Python Environment and Dependency Management

### uv

- A tool for managing Python versions, packages and virtual environments.
- Combines much of the functionality of pip, venv and pyenv.
- Can download a specific Python version without replacing my existing Python installation.
- Makes it easier to reproduce the same environment across different computers.

Useful commands:

- `brew install uv` — Install uv on Mac.
- `uv init` — Initialise a Python project.
- `uv python install 3.12` — Install Python 3.12.
- `uv python pin 3.12` — Specify the Python version for the project.
- `uv add pandas` — Install a dependency.
- `uv add --dev pytest` — Install a development dependency.
- `uv sync --locked` — Recreate the locked project environment.
- `uv run python app.py` — Run Python inside the project environment.

### pyproject.toml

- The main configuration file for a Python project.
- Contains the project name, version, dependencies and Python version requirements.
- TOML stands for Tom's Obvious, Minimal Language.
- With uv, it removes the need to maintain a separate requirements.txt file.
- Should be committed to GitHub.

### uv.lock

- Automatically generated by uv.
- Records the exact resolved versions of dependencies, including their dependencies.
- Helps keep development, testing and production environments consistent.
- Should be committed to GitHub.
- Should not normally be edited manually.

### .python-version

- Specifies which Python version the project should use.
- Allows different projects to use different Python versions.
- Should be committed to GitHub.

### .venv

- A virtual environment containing the project's Python environment and installed packages.
- Keeps dependencies isolated from other projects.
- Should not be committed to GitHub.
- Can be recreated using uv sync.

### requirements.txt

- A traditional file for listing Python dependencies.
- Commonly used with pip.
- Not necessary for this project because I am using pyproject.toml and uv.lock.

## 2. Git and GitHub

### Branches

- `main` — Stable production code.
- `test` — Code being tested before production.
- `feature/*` — Individual development tasks.

My preferred workflow:

Feature branch → Pull request → Test → Pull request → Main.

### .gitignore

- Tells Git which untracked files and folders to ignore.
- Useful for excluding secrets, virtual environments, caches and generated data.
- Does not automatically remove files already tracked by Git.

### .gitkeep

- Git does not track empty folders.
- Adding a .gitkeep file allows an otherwise empty folder to be included in the repository.
- It is a naming convention, not a special Git feature.

### Git staging

- `git status` — Check the current state of the repository.
- `git add` — Stage changes for a commit.
- `git commit` — Save a snapshot of staged changes locally.
- `git push` — Send local commits to GitHub.
- `gh pr create` — Create a pull request from the terminal.

## 3. Environment Variables

### .env

- Stores local configuration and secrets, such as API keys.
- Should not be committed to GitHub.

### .env.example

- A template showing which environment variables the project requires.
- Should not contain actual secrets.
- Should be committed to GitHub.

### python-dotenv

- A Python library that loads variables from a .env file into the application's environment.

## 4. Python Project Structure

### __init__.py

- Marks a directory as a regular Python package.
- Helps organise and import Python modules.
- Can be empty.

### src/

- Contains the main application logic.
- Separates application code from data, documentation and tests.

### tests/

- Contains automated tests.
- Helps identify problems when changes are made to the application.

### notebooks/

- Used for experimentation, data exploration and prototyping before writing production code.

### .github/workflows/

- Contains GitHub Actions workflow configuration.
- Used to automate testing, validation and deployment.
